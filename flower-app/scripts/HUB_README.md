# Fusion Investigator

A Flower AgentApp for investigating weak thermal response across synthetic
tokamak facilities. An investigator consults facility stewards, compares approved
evidence, rejects unsuitable analogies and recommends the next diagnostic check.

## Try the agent

Add **@marykor/fusion-investigator** to a Flower federation, open a new chat and
select Fusion Investigator. Try:

> Investigate weak thermal response at facility-a. Compare facility-b and
> facility-c, explain what remains uncertain, and recommend an independent
> measurement at A. Cite the evidence IDs.

Or use the Flower CLI after signing in:

```sh
flwr run @marykor/fusion-investigator supergrid --stream
```

The default model is `openai/gpt-5.6-sol`. Runs use the operator's Flower model
quota. The public app defaults to synthetic sites; no private connector or
reactor access is needed.

## What happens

1. The investigator discovers the available facilities and requests evidence.
2. Each facility steward uses a separate model context to decide whether to
   request a release from its software gateway.
3. The gateway enforces prerequisites, a five-unit allowance per facility and
   case, cached releases and the demo's gradient-based comparability criterion.
4. The investigator receives approved summaries and produces an advisory report
   with evidence IDs, uncertainty and a proposed next measurement.

Facility A uses DIII-D-like parameters, B SPARC-like parameters and C TCV-like
parameters. B's source audit can suggest a measurement for A; it does not diagnose A.
The facilities are simulated in this default deployment, not independently
connected reactors. Policy units are disclosure rules, not differential privacy.

## Was it trained on TORAX data?

No. The app uses a pretrained LLM through the Flower AgentApp runtime. We did not
train or fine-tune that LLM on TORAX data. The default evidence is generated by a
reduced one-dimensional steady-state thermal model; it is explicitly labelled
`reduced-1d-transport-v1`. It is not live TORAX execution or physical reactor data.

The separate TORAX/HFMARL research project evaluates control and cold-start
learning. Those results and training jobs are not bundled with this AgentApp.
Operators can configure snapshot or remote adapters separately. This agent
cannot actuate a reactor or launch control training.

## Interactive 3D dashboard

The custom web UI includes selectable 3D tokamaks, evidence requests, thermal
tools and reports. It runs locally from the
[separate application folder on GitHub](https://github.com/wolfeiq/tokamak-flower-berlin-2026/tree/codex/initial-snapshot/flower-app).
Flower Hub hosts the AgentApp and its source; this listing does not host that
custom dashboard. Use the repository's application README for setup.

## Build the agent sources

From this Flower project directory, with Python 3.11 or later:

```sh
uv sync
uv run flwr build
uv run fusion-investigator demo
```

The last command exercises deterministic toy tools without an LLM. Those
dimensionless toy cases are separate from the thermal facilities.
